# Release Notes - 2026.04.19
**Version:** 1.8.5
**Build Date:** 2026.04.19-5
**Module:** Core - Auth0 Login

---

## Summary
Fixed an Auth0 callback race where AppZ redirected `/` to `/home` before the Auth0 SDK could process the incoming `?code=...&state=...` callback parameters. This caused successful logins to degrade back into a guest session. The app now holds the callback route in place until Auth0 finishes initialization.

---

## Fixes
### 1. Auth0 Callback Route Protection
- Prevented the root index route from redirecting to `/home` while Auth0 callback parameters are present in the URL.
- Preserved the callback query string long enough for the Auth0 SDK to exchange the authorization code successfully.
- Avoided losing the Auth0 callback state during initial route bootstrap.

### 2. Auth0 Login Request Simplification
- Removed `audience` from the base `Auth0Provider` login configuration so the app can authenticate with standard `openid profile email` scope first.
- Kept audience-based token retrieval limited to optional post-login role resolution only.
- Added route preservation via `appState.returnTo` for login actions from both the auth screen and the header menu.

### 3. React Bootstrap Simplification
- Removed the global `StrictMode` wrapper from `src/main.tsx` to avoid double-invocation side effects during Auth0 redirect handling in development.

### 4. Visible Auth Error Handling
- Added Auth0 error display to the login screen so callback or tenant configuration issues are surfaced directly instead of appearing as a silent guest fallback.
- Removed temporary Auth0 debug logs from the header component.

### 5. Auth Initialization Guard
- Updated the main layout to keep the app in a loading state while Auth0 is initializing or while callback parameters are still being processed.
- Prevented guest UI from rendering prematurely during login completion.

### 6. Version Update
- Updated `src/core/config/appConfig.json` to version `1.8.5`.
- Updated build date to `2026.04.19-5`.
