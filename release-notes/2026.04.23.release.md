# Release Notes - 2026.04.23
**Version:** 1.8.7
**Build Date:** 2026.04.23-2
**Module:** Core - Auth0 API Access Token and API Test Menu

---

## Summary
Enabled reusable JWT bearer-token support for secured Web API calls from the Auth0-authenticated web application, and added a user-menu test action for `/api/health-check`. The app can now request an OAuth 2.0 access token on demand, attach it to outbound API requests through a shared core client, and verify the secured call from the UI.

---

## Fixes
### 1. Reusable API Access Token Retrieval
- Added a dedicated Auth0 hook to request Web API access tokens using the configured audience.
- Kept login initialization separate from API token retrieval so the prior Auth0 callback stability fix remains intact.
- Added an explicit configuration path for API-specific scopes.

### 2. Shared Authenticated API Client
- Added a core API client that attaches `Authorization: Bearer <token>` for secured requests.
- Centralized request URL creation, JSON body handling, JSON/text response parsing, and HTTP error mapping.
- Kept the client reusable for future feature modules and data sources.

### 3. Auth Configuration Expansion
- Added environment-driven support for `VITE_API_BASE_URL` and `VITE_AUTH0_API_SCOPE`.
- Updated role fallback token retrieval to use the dedicated API token parameters instead of the login scope.

### 4. Version Update
- Updated `src/core/config/appConfig.json` to version `1.8.7`.
- Updated build date to `2026.04.23-2`.

### 5. User Menu API Test Action
- Added a new authenticated menu action to invoke `/api/health-check`.
- Surfaced a masked bearer-token preview in the success notification so token acquisition is visible without exposing the full JWT.
- Surfaced API response details or HTTP error details directly in notifications for quick verification.
